# Technical Decisions

Each entry: decision, why, consequences. Newest last.

## TD-01 Greenfield project from Unity's own template settings
The repo was empty. ProjectSettings and URP assets were seeded from Unity 6000.3.27f2's bundled 3D cross-platform template, with a minimal package manifest (same versions as the owner's shipped turborush project). No third-party plugins: nothing can silently remove ARMv7 support.

## TD-02 Android configuration enforced in code (Redmi A3 lessons)
`ProjectConfigurator` sets IL2CPP, ARMv7+ARM64, min SDK 25, landscape, Vulkan with GLES3 fallback and a `.*PowerVR.*` Vulkan deny filter. In turborush, a Vulkan build on the Redmi A3 (PowerVR GE8320) crashed after a full close and relaunch; GLES3 fixed it. `AndroidBuildGuard` re-applies and checks this before every Android build; `Tools/verify_apk.sh` checks the APK independently of Unity.

## TD-03 Pure C# deterministic simulation, separate assembly
`VerdantSiege.Core` holds the battle simulation (`BattleSimulation`), grid, combat, waves, economy and save. It has no scene objects and no frame-time dependency: fixed 1/30 s steps, an 8-step cap per frame, and a seeded xorshift PRNG (`SeededRandom`, identical on every runtime). Presentation (`VerdantSiege.Game`) subscribes to simulation events and reads state; combat never waits for VFX or animation. Everything is testable in EditMode without scenes and replayable from a seed (needed later for daily challenges and expeditions).

## TD-04 Immutable ScriptableObject definitions, runtime state on pooled C# objects
Definitions (`DefenderDefinition`, `EnemyDefinition`, `ProjectileDefinition`, `StatusEffectDefinition`, `WaveDefinition`, `EncounterDefinition`, `BattlefieldDefinition`) are never written at runtime. Health, cooldowns, timers and statuses live on `DefenderRuntime`, `EnemyRuntime`, `ProjectileRuntime`, `PickupRuntime` and `DeckSlot`, pooled with an explicit `ResetForPool`. A test asserts that changing a definition does not alter a live runtime's health.

## TD-05 Lane positions in column units; world mapping only in BattleLayout
An enemy's `x` is its front edge in columns (0 = Heartroot edge). Contact, targeting and projectile sweeps are 1D per lane, so they are cheap and exact. `BattleLayout` is the only world↔grid conversion (cell 1 m x 1 m).

## TD-06 Objective: Heartroot health instead of per-lane last-chance devices
Enemies that reach the end damage the Heartroot (1 HP, Brute 2). The battle is lost at 0. This is more forgiving, readable and original than one-shot lane clearers, and it gives a natural "flawless" bonus.

## TD-07 Plated Brute armour = separate damage pool
Armour absorbs non-piercing damage before health. When it breaks, an event fires, the armour model is removed with debris, and the Brute speeds up (x1.35). Piercing damage bypasses armour, which Thorncaster (M3) will use as the counter.

## TD-08 Behaviours as stateless strategies
`IDefenderBehaviour` (LaneShooter, Blocker, Generator) keeps per-unit state on `DefenderRuntime`. New roster units add a behaviour class plus data, with no changes to the simulation loop.

## TD-09 All 3D art generated by scripted Blender
Per the owner's request, every model is generated by Python scripts in `Tools/Blender` (shared `vskit.py`, one script per model, `check_models.py` validation). Contract: metres, Z up, defenders face +X, enemies face −X, named parts with pivots at the joints, a single `Col` sRGB vertex-colour attribute whose alpha is an emission mask, and one material slot. Unity imports with baked axis conversion and imported normals; measured facing needs no correction. `ProjectSetup` syncs `Art/Models` into `Assets/_Game/Art/Models`; edit the generator, not the generated asset.

## TD-10 One vertex-colour shader for all models
`VerdantSiege/VertexLit` decodes the sRGB vertex colours to linear, adds wrapped main light, SH ambient and rim, uses vertex alpha as emission, and has a property-block hit flash plus optional vertex wind. It has no shadow maps and no additional lights, and is SRP-Batcher compatible. Blob shadows are flat quads. This keeps draw calls and the Redmi A3 GPU budget low while looking clean and stylised.

## TD-11 Procedural animation instead of skeletal rigs (for now)
`UnitRig` finds parts by name and poses them from cached rest poses: walk cycles driven by distance travelled, bite lunges, recoil, squash, cap pulses, damage stages and death sinks. Springs use sub-stepped semi-implicit integration. A bug found by the Linux autoplay showed that explicit Euler exploded at low FPS. Skeletal animation can replace this per unit later without changing gameplay.

## TD-12 UI built in code (uGUI + TMP), consistent kit
`UIKit` builds every screen from generated assets: rounded 9-slice sprites, an original procedural icon set, and Lilita One/Inter TMP fonts. No hand-made UI prefabs to drift. A full-screen transparent `BattleTapSurface` sits behind the HUD, so taps on widgets never reach the battlefield. Pickups are tested in screen space with a generous radius, and swiping collects them. Safe areas go through `ScreenSafe`, which can simulate a notch on desktop.

## TD-13 Procedural original audio
`AudioSynth` (editor) generates every SFX, music loop and ambience deterministically: no samples and no licensing risk. `AudioService` pools 12 voices with per-sound concurrency and rate limits; pause ducks the music.

## TD-14 Save format
JSON (JsonUtility) with a `version` field and a migration hook. Writes go to a temp file, then the previous file is kept as `.bak`, then the temp file is moved into place. Recovery order: primary, backup, then reset (the corrupt file is kept as `.corrupt`). A save from a newer version is never overwritten.

## TD-15 Automated verification layers
- EditMode: simulation rules, save, content validation, and a scripted-player balance test over 5 seeds, plus a defenceless-loss test.
- Linux test player autoplay (`-vs-autoplay`): plays through the real UI input path with screenshots and checks pause/resume at several aspect ratios and notch insets.
- APK inspection script.

Real-device runs remain mandatory and are tracked separately.

## TD-16 Camera: perspective, auto-fitted to the HUD-free viewport
54° pitch, 32° FOV. `BattleCameraRig` fits the field plus Heartroot and entry margins into the area outside the card rail and top bar, for any aspect from 4:3 to 21:9, and refits on resolution or safe-area changes.
